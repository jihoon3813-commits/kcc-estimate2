# 안티그래비티에 전달할 작업 지시

이 폴더는 KCC홈씨씨 모바일 창호 견적서의 완성된 디자인 시안이다. 제공된 디자인과 문구를 유지하면서 기존 견적 시스템에 연결할 수 있도록 개발을 이어가라.

## 먼저 확인할 파일

`README.md`, `DEVELOPMENT_NOTES.md`, `web/index.html`, `web/styles.css`, `web/app.js`를 읽고 `npm run dev`로 현재 화면을 확인하라. 외부 패키지 설치는 필요하지 않다.

## 디자인 유지 기준

- 화이트·딥네이비·오렌지 색상, 금액 강조, 여백, 카드 형태와 모바일 화면 구성을 유지한다.
- 페이지 순서는 고객 견적 요약 → 결제 비교 → 포함 내역·업그레이드 → 창호 상세 → FAQ → 상담 요청 → 가전·주방 추가 혜택이다.
- 고객이 초기 납입액·월 납부액·납부기간·총 납부액을 함께 확인할 수 있게 한다.
- 모바일 하단 고정 상담 버튼과 상세 사양 아코디언, 상담 바텀시트를 유지한다.
- 별도의 디자인 리뉴얼, 가격 변경, 임의의 추가 할인·보증·인기 배지·후기를 만들지 않는다.

## 개발 순서

1. 현재 정적 화면을 실행하고 디자인과 상호작용을 파악한다.
2. 고객·견적·결제조건·창호·혜택·담당자 데이터를 하나의 견적 모델로 분리한다. 현재 HTML과 JavaScript에 반복된 금액을 같은 데이터에서 출력한다.
3. 실제 연결할 기존 시스템의 데이터 형식과 엔드포인트가 제공되어 있다면 해당 연동을 사용한다. 제공되지 않았다면 연동 어댑터 경계와 예시 데이터만 준비하고 실제 연결이 끝났다고 표시하지 않는다.
4. 상담 요청에는 견적 ID, 선택 결제 방식, 선납금, 상담 주제, 희망 시간, 추가 메모를 포함한다. 서버 저장 성공 이후에만 실제 접수 완료를 보여준다. 로딩·실패·재시도·중복 접수 방지 상태도 구현한다.
5. 고객 연락처는 견적의 고객 데이터로, 전화 버튼은 검증된 담당자 연락처로 연결한다. 두 번호를 혼동하지 않는다. 연락처 수정 흐름이 필요하면 본인 확인 기준에 맞춰 추가한다.
6. 고객별 조회를 연결할 때 단순 이름·전화번호 URL만으로 타인 견적을 열 수 있는 구조를 피하고, 기존 시스템의 인증 또는 접근 토큰·만료 정책을 적용한다.
7. 실연동과 검수가 끝난 기능에 한해서만 ‘디자인 미리보기’ 안내를 실제 운영 문구로 바꾼다. 동작하지 않는 접수·전화 기능을 작동하는 것처럼 보이게 하지 않는다.

## 제공 전 확인할 사항

- 원본 표시 합계 11,556,600원과 개별 항목 합계 11,556,674원의 74원 차이는 원본 시스템의 정산 기준을 확인한다. 임의로 항목 금액을 바꾸지 않는다.
- 구독 월 납부액은 승인된 산식이 제공되기 전까지 임의로 계산하지 않는다. 현재 계산기는 구독 전환 대상 금액만 계산한다.
- 보증·프로모션의 적용 대상, 기간, 조건은 운영 데이터에서 관리한다.
- 거실·주방 사진은 디자인용 공간 연출 이미지다. 실제 고객 배포 전에는 승인된 브랜드 이미지로 교체하고 출처 문서를 참고한다.

## 완료 기준

모바일 360·390·430px, 태블릿, PC에서 가로 넘침과 버튼 가림이 없어야 한다. 결제 조건이 상담 데이터와 일치하고, 상담 저장 실패를 성공으로 표시하지 않아야 한다. 변경 내용, 검증 결과, 아직 연결되지 않은 부분을 구분해서 보고하라.
